## 4. Isolated Real-AI Worker Architecture & RD-09 Term-1 Exception Draft

### 4.1 Why an Isolated Local Worker Subprocess Is Preferred

1. **Preserves C1/M1c Invariants:** `backend/app/main.py` never imports `ai/` or `sklearn`/`joblib`/`numpy`, keeping `tests/backend/test_inference_provider.py` 100% intact.
2. **Deserialization & Secret Containment:** `joblib.load` (`pickle`) and `shap_background.npz` (training-derived rows) plus the local HMAC signing key live **exclusively** inside the isolated worker process and trusted local bundle directory. The web backend process never reads `local_bundle_hmac_v1.key`, never opens `.joblib`/`.npz` files, and never sees raw training-background rows.
3. **Zero Patient Identity Leakage:** The backend constructs an **anonymized, strictly typed inference request payload** containing only:
   - `assessment_id` (opaque UUID), `generation`, `fence_token`
   - `model_id` (`cai_real_da-a2_da_a2_resting_v1`), `panel_id` (`da_a2_resting_v1`), `panel_contract_sha256`
   - `source_provenance` (server-assigned enum: `synthetic_demo_patient_manual` | `synthetic_demo_ocr_confirmed` | `clinician_verified_demo`)
   - `features` (5 resting fields in panel contract schema), `units`, `missing_reasons`
   - `lime_seed` (deterministic integer derived from `(assessment_id, snapshot_sha256)`)
   It **never** passes `user_id`, `patient_id`, `email`, `DEMO-ID-nnn`, `subject_label`, `doctor_id`, uploaded report files, or OCR raw text.
4. **Fail-Closed Startup & Per-Call Verification:**
   - Environment configuration: `CARDIOASSIST_C2_AI_MODE` defaults to `"disabled"` (no environment variable can activate real AI without **both** explicit operator activation config **and** a compiled/verified `RATIFIED_TERM1_DEMO_AI_SCOPES` registry entry — matching `ai/diagnostic_scope.py`'s defense-in-depth pattern where an env var alone is never sufficient!).
   - When disabled or unratified (`A3` pending): backend **never** spawns the worker, transitions the assessment deterministically to `INFERENCE_UNAVAILABLE` (or `503` on explicit trigger if preferred, see `API Spec`), creates **zero** `inference_result` rows, and **never** falls back to `MOCK_SYNTHETIC`.
   - When authorized (`A3` granted): backend spawns or communicates with the local worker (`python` from the pinned worker venv, `shell=False`, fixed executable path verified against allowlist, no user-controlled CLI args, `PYTHONPATH` pinned, hard wall-clock timeout e.g. `30s`, output byte cap e.g. `512 KiB`).
   - Inside the worker:
     1. Re-verify `RATIFIED_TERM1_DEMO_AI_SCOPES` entry against `ai/diagnostic_inference.py::verify_accepted_bundle_identity`.
     2. Run `ai/packaging.py::verify_trusted_local_bundle(bundle_dir, trusted_local_root=..., signing_key=...)` (checking DACL/POSIX perms, no symlinks, no quarantine marker, `POST_RUN_ACCEPTANCE.json`, SHA-256 of every file, HMAC producer attestation).
     3. Validate input panel & `source_provenance` against `DA_A2_RESTING_PANEL` (`da_a2_resting_v1`, `contract_sha256`).
     4. Load `ResearchCadPredictor.from_verified_bundle(...)` and run prediction (`calibrated_research_score`, `calibrated_log_odds`, `raw_model_score`, `raw_model_log_odds`, outer-fold dispersion), grouped LinearSHAP (`explain_clinical_instance` with `sum_check_passed == True`), and certified LIME (`explain_clinical_instance_lime_certified`).
     5. Return strict JSON response containing `manifest_sha256`, `panel_contract_sha256`, scores, SHAP, LIME (+ quality status), and limitations — **zero** background samples, **zero** file paths, **zero** secrets.
   - Back in the backend inside a `BEGIN IMMEDIATE` transaction:
     - Re-verify `assessment.current_generation == generation`, `attempt.fence_token == fence_token`, `attempt.lease_expires_at > now` (or valid active attempt), `doctor_patient_assignment.revoked_at IS NULL`, and `consent_record.revoked_at IS NULL` before committing `inference_result` + `current_result_id` + `status = 'PENDING_REVIEW'`.

## 5. Bounded Document Intake & Fixed-Template Local OCR Design

### 5.1 Authored Fabricated Templates (Zero Real Scans / Zero PHI)

1. **Primary Resting Assessment Template (`CAI-DEMO-RESTING-CARDIAC-REPORT-V1`):**
   - Project-authored synthetic English PDF & PNG/JPEG fixture templates bearing a prominent header/watermark: `SYNTHETIC DEMO REPORT — NOT A REAL PATIENT RECORD`.
   - Anchored key-value layout containing **explicit labels, values, units, and source codes** for the 5 `da_a2_resting_v1` fields:
     - `Template ID:` `CAI-DEMO-RESTING-CARDIAC-REPORT-V1`
     - `Age:` `<int> years`
     - `Sex:` `0 (Female)` or `1 (Male)` (anchored code + label)
     - `Chest Pain Category (cp):` `1..4` (explicit code `1=Typical Angina`, `2=Atypical Angina`, `3=Non-Anginal Pain`, `4=Asymptomatic`)
     - `Resting Systolic BP (trestbps):` `<number> mmHg` (or `NOT_MEASURED` / `NOT_AVAILABLE`)
     - `Resting ECG Classification (restecg):` `0`, `1`, or `2` (or `NOT_MEASURED`; patient/template supplies classified code, **never** raw ECG waveform interpretation!)
2. **Secondary Unrelated-Labs Demo Template (`CAI-DEMO-UNRELATED-LABS-V1`):**
   - Fabricated English routine-lab attachment (`Total Cholesterol`, `Fasting Blood Sugar`, `LDL`, `HDL`, `Creatinine`, `Hemoglobin`, `WBC`) accepted as a relevant clinical attachment for doctor viewing, while **strictly excluded** from `da_a2_resting_v1` extraction/autofill/inference (proving non-ingestion of unverified labs).

### 5.2 Hardened File Admission, Containment & Parser Limits

| Control | Frozen Proposal |
|---|---|
| **Allowed formats** | `application/pdf`, `image/png`, `image/jpeg` — verified by **magic bytes** (`%PDF-`, PNG signature, JPEG SOI/EOI), **not** filename extension or `Content-Type` header alone |
| **Size / page / pixel caps** | Max `5 MiB` (`5,242,880` bytes) per file; max `3` pages per PDF; max `4096 x 4096` pixels (`16,777,216` max pixels, decompression-bomb check before full decode); max `5` attachments per assessment and `20` active documents per patient |
| **Active/hostile content rejection** | Reject encrypted/password-protected PDFs, PDFs containing `/JavaScript`, `/JS`, `/OpenAction`, `/Launch`, `/EmbeddedFile` (active/embedded content), corrupted/truncated files, and mismatched declared vs magic MIME (`415 unsupported_media_type` or `422 invalid_document_content`) |
| **Private storage layout** | Stored outside Git and outside static web roots (configurable `CARDIOASSIST_DOCUMENT_STORE_DIR`, defaulting to `./var/private_documents`, `0700` / private DACL). Server-generated UUID filename `<patient_uuid>/<document_uuid>.bin`; original filename sanitized to display metadata only and **never** used in filesystem paths. Symlinks, junction points, `..`, and reparse points rejected (`ai/filesystem_security.py` semantics). |
| **Atomic DB + File Lifecycle** | Upload computes SHA-256 while streaming within size cap, writes to a private temp file, verifies magic/PDF/image bounds, moves atomically into `<store>/<patient_id>/<document_id>.bin`, then commits `medical_document` inside `BEGIN IMMEDIATE`. If DB commit fails, temp/target file is unlinked; periodic orphan-reconcile helper cleans unreferenced temp files safely without ever deleting committed evidence. |
| **Private download/view (`DOC4`/`DOC8`)** | Authenticated owner-patient or currently-assigned active doctor only (`404` on wrong owner, revoked doctor, or admin). Serves `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`, `Content-Disposition: attachment; filename="demo-report-<short_id>.<ext>"` (or `inline` only for verified PDF/PNG/JPEG when requested with `?disposition=inline` and strict `nosniff` + sandbox CSP). Verifies `SHA-256(bytes_on_disk) == medical_document.content_sha256` before streaming (`500` / tamper event if mismatch!). |

### 5.3 Real Local OCR Extraction, Failure Handling & Provenance

1. **No Cloud, No Hardcoded Autofill:** Text-layer PDFs use local deterministic PDF text extraction (e.g., `pypdf` / `pymupdf` text layer); scanned/raster PDFs and PNG/JPEG images render/preprocess via `Pillow` / `pypdfium2` (or `pymupdf` rasterizer) and execute **local Tesseract OCR** (`tesseract` binary + `pytesseract`, pinned version) in a bounded subprocess/worker (`timeout = 15s`, `shell=False`).
2. **Anchored Template Parsing & Conflict Rules:**
   - First check for exact `Template ID:` (`CAI-DEMO-RESTING-CARDIAC-REPORT-V1` or `CAI-DEMO-UNRELATED-LABS-V1`) and synthetic watermark token. Unrecognized templates return `extraction_status = "UNSUPPORTED_TEMPLATE"` (`422` or non-autofill status; original document remains safely stored for doctor inspection!).
   - Parse each field by anchored regex/region. If a field appears **more than once with conflicting values**, mark `conflict_flag = True`, `parse_status = "CONFLICT_REVIEW_REQUIRED"`, and leave `typed_value_json = None` (force manual patient entry/resolution!).
   - If OCR confidence (when engine provides per-word/line confidence; nullable if text-PDF or unavailable) is below threshold (`< 0.75` / `75%`) or unit/category parsing fails (`trestbps` missing `mmHg`, `cp` outside `{1..4}`), set `parse_status = "LOW_CONFIDENCE"` / `"INVALID_VALUE"` and leave `typed_value_json = None` so the patient must inspect and enter/confirm manually.
3. **Explicit Patient Edit & Confirmation (`DOC7`):**
   - OCR extraction **never** auto-confirms fields, **never** writes directly to `health_profile` without confirmation, and **never** submits an assessment.
   - Patient submits `POST /v1/me/documents/{document_id}/confirm` with explicit confirmed field values, optional manual corrections, and `confirm_fabricated_demo_inputs: true`.
   - Server records an append-only `extraction_event` (`PATIENT_CONFIRMED` + `field_diffs_json`) and computes field-level provenance:
     - untouched OCR-parsed field → `ocr_extracted_patient_confirmed`
     - patient-edited or manually filled OCR-missing field → `patient_entered_from_ocr_draft`
4. **Fabricated-Demo Provenance Exception (`PROPOSED — REQUIRES EXPLICIT RATIFICATION`):**
   - **Rule preserved:** Under `F14`/`F15`, patient confirmation is **not** clinician verification (`clinician_verified_against_source` requires `DOCTOR_VERIFIED` in C3).
   - **Why an exception is needed:** `O-12` requires the local educational demo to support pre-doctor-review OCR-assisted intake feeding the provisional research result (once `A3` + `B` are granted), without falsifying provenance as manual entry or clinician-verified clinical data.
   - **Proposed closed `source_provenance` enum on `assessment`:**
     1. `synthetic_demo_patient_manual` — patient manually entered/confirmed values without OCR autofill (optional attached reports for doctor viewing).
     2. `synthetic_demo_ocr_confirmed` — patient confirmed/edited values originating from fixed-template local OCR under the ratified **Fabricated-Demo OCR Provenance Exception** (`EXC-TERM1-OCR-DEMO-V1`).
     3. `clinician_verified_demo` — values attested/verified by an assigned doctor against attached reports (`DOCTOR_VERIFIED`).
   - **Fail-closed guard:** Until `EXC-TERM1-OCR-DEMO-V1` + `A3` are explicitly ratified, `S1` (`POST /v1/me/assessments`) with `source_provenance = "synthetic_demo_ocr_confirmed"` either returns `403 ocr_inference_not_authorized` (if user explicitly selects OCR-derived inference) or records `INFERENCE_UNAVAILABLE` if C2 safe-scope is active — **never** silently relabels OCR values as `synthetic_demo_patient_manual`. Manual entry (`synthetic_demo_patient_manual`) remains independently exercisable at all times.
