## 4. Isolated Real-AI Worker Architecture & RD-09 Term-1 Exception Draft

### 4.1 Why an Isolated Local Worker Subprocess Is Preferred

1. **Preserves C1/M1c Invariants:** `backend/app/main.py` never imports `ai/` or `sklearn`/`joblib`/`numpy`, keeping `tests/backend/test_inference_provider.py` 100% intact.
2. **Deserialization & Secret Containment:** `joblib.load` (`pickle` inside `model.joblib`) and `shap_background.json` (training-derived rows) plus `local_bundle_hmac_v1.key` live **exclusively** inside the isolated AI worker process and trusted local bundle directory. Neither the web backend process nor the OCR worker process ever reads `local_bundle_hmac_v1.key`, opens `model.joblib`, or sees `shap_background.json` rows.
3. **Zero Patient Identity Leakage:** The backend constructs an **anonymized, strictly typed inference request payload** over authenticated loopback IPC (`POST /internal/ai/v1/infer` with bearer `CARDIOASSIST_AI_WORKER_IPC_TOKEN`) containing only:
   - `assessment_id` (opaque UUID), `attempt_id`, `generation`, `fence_token`, `worker_id`
   - `model_id` (`cai_real_da-a2_da_a2_resting_v1`), `model_version` (`0.2.0`), `panel_id` (`da_a2_resting_v1`), `panel_version` (`1.0.0`), `panel_contract_sha256`
   - `source_contract_version` (`term1.c2.intake/v1`), `source_kind` (strictly server-assigned enum: `synthetic_demo_patient_manual` | `synthetic_demo_ocr_confirmed`)
   - `features` (5 resting fields in `da_a2_resting_v1` schema), `units`, `missing_reasons`
   - `lime_seed` (deterministic integer derived from `(assessment_id, snapshot_sha256)`)
   It **never** passes `user_id`, `patient_id`, `email`, `DEMO-ID-nnn`, `subject_label`, `doctor_id`, uploaded report files, or OCR raw text.
4. **Separate Verification (`operation=verify_only`) vs Activation (`operation=activate`) & Fail-Closed CAS:**
   - **Pre-`A3` (`CARDIOASSIST_C2_AI_MODE = "disabled"`):** backend **never** invokes `/internal/ai/v1/infer`, inserts an `inference_attempt` in `INFERENCE_UNAVAILABLE` (`reason_code = "real_ai_not_authorized"`), keeps `active_attempt_id = NULL` and `current_result_id = NULL`, inserts **zero** `inference_result` rows, and **never** falls back to `MOCK_SYNTHETIC`.

No env var alone can activate real AI.
   - **Worker execution & atomic completion CAS (C0 §7.3):**
     1. Backend creates `inference_attempt` (`state = 'INFERENCE_RUNNING'`, `generation = assessment.current_generation`, `worker_id`, CSPRNG `fence_token`, `lease_until = now() + 300s`), sets `assessment.active_attempt_id = attempt_id`, sets `assessment.status = 'INFERENCE_RUNNING'`, and invokes `POST /internal/ai/v1/infer` (`shell=False` / loopback HTTPS-or-HTTP localhost IPC, `30s` worker timeout, `512 KiB` response cap).

Inside `BEGIN IMMEDIATE`, backend enforces **every** C0 §7.3 CAS invariant: `attempt_id`, `assessment_id`, `attempt.generation == assessment.current_generation`, `assessment.active_attempt_id == attempt_id`, `attempt.state == 'INFERENCE_RUNNING'`, `assessment.status == 'INFERENCE_RUNNING'`, `attempt.worker_id == submitted.worker_id`, `attempt.fence_token == submitted.fence_token`, **strictly `attempt.lease_until > now()`**, active `assignment_id` (`revoked_at IS NULL`), exact referenced `consent_id` (`revoked_at IS NULL`), active `A3`, and verified `snapshot_sha256` & `result_sha256`.

     5. Stale/non-active completions (mismatching `active_attempt_id`, `generation`, `fence_token`, `worker_id`, or `lease_until <= now()`) are rejected (`409 stale_attempt_fenced`) with zero DB mutations.
