## 3. Additional required design corrections

- **R-01 relational ownership:** remove the proposed `patient.doctor_id` ownership predicate; authorize via active assignment and intended assessment's assignment. Enforce cross-entity consistency with appropriate FK/unique/check constraints and transaction-level validation. Freeze policy for historical assessments/messages after revocation; do not allow a newly assigned doctor to read unrelated historical results. Explicit patient selection of treating assignment if more than one is active.
- **R-02 visit and identity binding:** bind the intended fictitious identity at verified visit attestation, before issuing an invitation; prevent a code for patient B on patient A's attested visit. Freeze normalization/strict allowlist, unambiguous HMAC encoding, purpose/key separation, rotation and uniqueness across versions. Do not store raw identifiers or treat matching as real-world identity proof. Define authoritative server timestamps separate from stated visit time. No arbitrary clinical free-text in demo attestation.
- **R-03 complete enrollment API:** missing explicit invitation revoke operation, existing-account link/accept flow, assignment revocation and account lifecycle (suspension and credential change if required). Align endpoint inventory, ERD, and tests. Decide login lockout error semantics without enumeration (Arena's 423 vs generic 401 conflict). Decide session transport and anti-CSRF/CORS/secret boundaries. Admin bootstrap local, no default credentials. Fix visit/doctor indexes to use actual columns; no nonexistent doctor_id in invitation or status in session.
- **R-04 idempotency and secrets:** no generic response_json storing raw access codes/credentials/sessions. One-time disclosure and lost-response behavior explicitly defined; enrollment retry must not create a second account/assignment or mint a session by replay. Failed attempts increment durably outside rolled-back business transaction with privacy-safe rate limiting; test failure/lockout/retry behavior. Do not claim exactly-once distributed execution from a database key.
- **R-05 inference consistency:** one authoritative result row, not duplicated score/explanation on attempt and result. Explicit attempt generation/lease/fencing and CAS completion prevents late worker success after recovery; result must bind snapshot/model/source. Preserve authorized historical evidence, hide stale/failed current results rather than destructively erase history. Define review conflicts and follow-up eligibility. C3 test doubles may be injected only in tests, never as actual trained results or production bypass.
- **R-06 contracts and tooling:** choose a canonical served combined spec or deterministic bundling with complete operation allowlist and original operation-level coverage. Headers are not JSON body fields. Freeze error/status/replay, authorization/redaction rules and fixtures including revocation. C0 contracts are design proposals under docs, not changes to runtime/shared contracts. All implementation contracts reviewed at C0/C1 boundaries.
- **R-07 verification:** Windows PS5.1 native command exit codes must be checked explicitly, not only `$ErrorActionPreference='Stop'`. Reuse same verified clone safely with `fetch` and `merge --ff-only`, assert expected head/branch/remote/clean status, use fresh disposable DB per test and separate upgrade-preservation DB, correct Python version, pinned dependencies and full-suite research dependency prerequisites. No broad `pytest -k` acceptance in place of exact test paths. No cleanup/delete/reset or invented endpoints. C0 baseline only, then stage-specific smoke and restart evidence.
- **R-08 governance/AI:** agree full target scope now but no automatic grant of A/B. Exact candidate B is a genuine synthetic-trained educational candidate, not clinical performance evidence. Define source-specific panel, artifact/digests/scale, same-model SHAP and LIME requirements or explicit accepted alternative, pinned deterministic oracle/trust/distribution and tamper tests. New authorization must address RD-09 and relevant research governance, not a header/env flag. Real data/private Cleveland not transferred or executed. Score display only after B; no individual future risk, diagnosis, treatment recommendation, or AI prescription. If a blocker persists, report not complete; no implicit reduced scope.
